# Финансовый питомец — сопроводительная документация

Игровое мобильное приложение для детей 7–11 лет: ребёнок заботится о лисёнке Рыжике и учится распоряжаться игровыми монетами — планировать бюджет, отличать важные траты от желаний, копить на цель и распознавать мошенников.

| Параметр | Значение |
|---|---|
| Название | Финансовый питомец |
| Имя пакета (applicationId) | `ru.financepet.ryzhik` |
| Версия (versionName) | 1.0.0 |
| Номер сборки (versionCode) | 1 |
| Платформа | Android 7.0+ (minSdk 24), targetSdk 36; проверено на Android 8.0+ по ТЗ |
| Стек | Flutter 3.47.4 (stable), Dart 3.13.3, SQLite (sqflite) |
| Репозиторий | https://github.com/VavilonK/Hackathon |
| Сборка | `build/app/outputs/flutter-apk/app-release.apk` (подписанный релизный APK), `app-release.aab` |

Версия и номер сборки задаются одной строкой в `pubspec.yaml` (`version: 1.0.0+1`: до «+» — versionName, после — versionCode). Для каждой новой сдачи номер сборки увеличивается на 1.

## 1. Назначение продукта и состав репозитория

**Проблема.** Дети 7–11 лет рано сталкиваются с деньгами (карманные деньги, покупки в школе, онлайн-игры), но навыки планирования, накопления и безопасного обращения с деньгами формируются позже. Абстрактные объяснения скучны, а ошибки с реальными деньгами дорого стоят.

**Решение.** Безопасная игровая среда: ребёнок получает игровые монеты за задания, распределяет их по трём направлениям («на важное», «на приятное», «в копилку»), покупает Рыжику еду, уход и игрушки, копит на цель. Состояние и рост питомца зависят от финансовых решений за несколько игровых дней. Реальные деньги, реклама и покупки отсутствуют.

**Состав репозитория**

| Путь | Содержимое |
|---|---|
| `lib/app/` | Точка входа, корневой виджет, оболочка с нижней навигацией |
| `lib/core/state/` | `AppController` — единое состояние и игровая экономика; `AppScope` — доступ из UI |
| `lib/core/storage/` | SQLite: база, репозиторий профилей, снимок состояния (`AppStateSnapshot`), сериализаторы |
| `lib/core/theme/`, `lib/core/widgets/` | Дизайн-система: цвета, шрифты, отступы, общие кнопки и карточки |
| `lib/features/<модуль>/` | Функциональные модули (см. раздел 3), внутри — `domain` (модели и правила), `data` (контент и хранилища), `presentation` (экраны) |
| `assets/` | Иллюстрации, анимации Рыжика (WebP 60 fps), шрифт Nunito, иконки |
| `assets/branding/` | Иконка приложения 1024 × 1024 |
| `test/` | 24 файла автотестов (427 тестов) |
| `tool/generate_app_icon.py` | Генератор иконок для Android, iOS и веба |
| `docs/` | Документация, карточка RuStore, презентация, скриншоты |

**Быстрый запуск** — см. `README.md` (установка готового APK или `flutter run`).

## 3. Функциональная и компонентная архитектура

Серверной части нет: всё работает офлайн на устройстве, поэтому OpenAPI и схема развёртывания не требуются.

### 3.1. Слои

```
UI (features/*/presentation)  ──читает──►  AppScope (InheritedNotifier)
        │ действия пользователя                   │
        ▼                                          ▼
AppController (core/state) — игровая экономика, правила, периоды
        │ снимок состояния                │ проводки
        ▼                                  ▼
AppStateRepository (SQLite)      FinancialTransactionRepository (SQLite)
        ▲
Учебный контент (features/*/data): шаблоны заданий, локации, демо-дни, события, магазин
```

- **Экономика и правила** — `AppController` и доменные классы (`PetProgressionPolicy`, `BudgetPlan`, `ShopCatalog`, `GameEvents`). UI не меняет баланс напрямую, а вызывает методы контроллера (`buyItem`, `addToSavings`, `completeTask`, `resolveEvent`…).
- **Учебный контент** отделён от интерфейса: шаблоны заданий (`missions/data/daily_task_templates.dart`), генератор ежедневной миссии (`daily_mission_generator.dart`), локации (`tasks/data/location_definitions.dart`), сценарий демо-дней (`periods/data/demo_period_definitions.dart`), события (`events/domain/game_event.dart`), каталог покупок (`shop/domain/shop_catalog.dart`).
- **Хранение** — SQLite: снимок профиля (JSON) и журнал финансовых операций.
- **UI** — экраны модулей на общей дизайн-системе (`core/theme`, `core/widgets`).

## 4. Структура данных

### 4.1. Хранилище

| Таблица SQLite | Назначение |
|---|---|
| `app_state` | Снимок профиля: `id`, `schema_version`, `payload_json` (JSON `AppStateSnapshot`); отдельные записи для обычного и демо-профиля |
| `app_metadata` | Служебные ключи (активный профиль и т. п.) |
| `financial_transactions` | Журнал операций: id, профиль, игровой период, тип, источник, сумма, баланс и копилка до/после, время |

PIN взрослого хранится не в SQLite, а в зашифрованном хранилище ОС (`flutter_secure_storage`: шифрование ключом из Android Keystore).

### 4.2. Профиль и экономика (`AppStateSnapshot`)

| Группа | Поля |
|---|---|
| Ребёнок | игровое имя, возраст (7–11), уровень сложности (junior/middle/senior) |
| Кошелёк | `balance` — монеты в кошельке; `savings` — копилка |
| Бюджет | `budgetPlan` (на важное / на приятное / в копилку), `budgetPlanConfirmed`, `budgetUsage` (потрачено на важное/приятное) |
| Цель | `selectedGoalId`, завершённые цели |
| Питомец | `petState` (настроение, сытость, забота 0–100, время кормления/игры/поглаживания), `petGrowthPoints`, внешний вид (цвет худи, аксессуары), имя питомца, купленные игрушки |
| Задания | активная миссия, индекс задания, счётчики выполненных, недавние локации и шаблоны (чтобы не повторяться) |
| Периоды | активный `GamePeriod` и список завершённых |
| Режим | `runMode` (normal/demo), `demoPeriodIndex` (1–5) |
| События | ожидающее и отложенное событие, ключ дня последней проверки |
| Настройки | звук, подсказки, просмотр знакомства |

### 4.3. Игровой период (`GamePeriod`)

Один игровой день. Хранит: баланс и копилку на начало и конец, план бюджета на момент подтверждения, заработано, потрачено на важное/приятное, отложено в копилку (в т. ч. осознанно), число заданий (всего, выполнено, верно; из них финансовых), прогресс цели на начало и конец, состояние питомца на начало и конец, начисленные очки роста с разбивкой, стадию до и после, пройденные темы.

### 4.4. Задание (`MissionTask`)

`templateId`, тема (`math`, `finance`, `logic`, `memory`, `attention`, `entertainment`), тип (расчёт, выбор, классификация, сопоставление, распределение бюджета…), экономический тип (`simulation` — учебная ситуация, `earning` — приносит монеты, `realExpense` — реальная трата из кошелька), текст, варианты ответа с суммой и категорией, правильный ответ, награда в монетах, объяснение.

### 4.5. Финансовая операция (`FinancialTransaction`)

Типы: `earning`, `essentialExpense`, `wantExpense`, `savingsDeposit`, `savingsWithdrawal`, `goalPurchase`, `loss`. Источники: `mission`, `petCare`, `miniGame`, `savings`, `system`, `parent`, `event`. Каждая операция хранит баланс и копилку до и после — поэтому любое изменение баланса объяснимо (ТЗ 2.5.4).

## 6. Правила расчёта

### 6.1. Баланс и копилка

- `balance` — монеты в кошельке, `savings` — в копилке. Оба значения никогда не становятся отрицательными: покупка или списание выполняется только при `balance ≥ цена`, иначе показывается «не хватает N монет» и варианты (задания, покупка дешевле, отложить).
- **Доход:** награда за задание (15–20 монет за задание с заработком; учебные задания без монет), распределение награды между кошельком и копилкой (задание «Раздели награду»), начисление от взрослого, +5 за правильное поведение в событии «звонок мошенника».
- **Расход «на важное»:** еда, уход, ветеринар. **«На приятное»:** вкусняшка, игрушки для комнаты. Каждая трата увеличивает соответствующее «потрачено» в `budgetUsage` и записывается в журнал.
- **Копилка:** перевод «в копилку» уменьшает кошелёк и увеличивает копилку; снятие требует подтверждения и показывает, насколько уменьшится накопленное. Прогресс цели = `min(1, savings / цена цели)`.
- **Бюджет:** сумма распределения должна равняться доступному балансу (`распределено = balance`), интерфейс показывает остаток к распределению; при новых монетах план можно дополнить.

### 6.2. Покупки и состояние питомца

| Позиция | Цена | Категория | Эффект |
|---|---:|---|---|
| Корм | 20 | важное | Сытость +30, Настроение +4 |
| Полезный перекус | 35 | важное | Сытость +22, Забота +3, Настроение +8 |
| Вкусняшка | 50 | приятное | Сытость +15, Настроение +15 |
| Щётка | 20 | важное (уход) | Забота +20 |
| Набор для купания | 35 | важное (уход) | Забота +30, Настроение +5 |
| Плюшевый мишка | 60 | приятное (комната) | Настроение +15, остаётся в комнате |
| Гирлянда-звёзды | 80 | приятное (комната) | Настроение +20, остаётся в комнате |
| Пуфик | 100 | приятное (комната) | Настроение +25, остаётся в комнате |

- Показатели питомца — от 0 до 100.
- **Со временем:** каждые 15 минут сытость −3, забота −2, настроение −2. Каждая игрушка в комнате замедляет падение настроения на 10 % (не больше 50 %).
- **Голод:** Рыжик голоден, если сытость < 30 — меняется анимация и реплика с объяснением причины.
- **Поглаживание и мини-игры** поднимают настроение (мини-игра: +10 при первом прохождении за день и +2 XP, далее +3 без XP — защита от «фарма»).

### 6.3. Рост питомца

После каждого игрового дня начисляются очки роста (максимум 30 за день):

| Критерий | Очки |
|---|---|
| Бюджет подтверждён до трат | 4 |
| Траты в рамках плана (допуск +20 %, минимум 20 монет): без превышения 5; превышение до 35 % — 4; до 75 % — 3; до 125 % — 2; больше — 1 | до 5 |
| Отложено в копилку относительно личной цели дня (план «в копилку» или 10 % доступных монет): ≥ 100 % — 7; ≥ 60 % — 6; ≥ 30 % — 5; меньше — 4 | до 7 |
| Продвижение к цели (та же шкала): 4 / 3 / 2 / 1 | до 4 |
| Точность финансовых заданий: ≥ 80 % — 6; ≥ 60 % — 4; ≥ 40 % — 2; хотя бы одно верное — 1 | до 6 |
| Выполнены все задания миссии | 4 |

Стадия определяется суммой очков: **малыш** < 40, **подрос** 40–89, **старший** ≥ 90. Рост возможен только по совокупности нескольких дней, а разбивка очков показывается на экране итогов дня.

## 7. Карта образовательного контента

| Тема | Ожидаемый навык | Сценарии (шаблоны) | Правильная логика | Объяснение ребёнку (пример) |
|---|---|---|---|---|
| Планирование бюджета | Распределять доход по направлениям до трат | «Раздели бюджет» (`split_budget`), экран «Бюджет», «План и факт» | Сначала важное, затем копилка, остаток — на приятное; сумма = доступному | «Сначала важное: еда и уход. Приятное — если останутся монеты» |

**Как добавить задание:** описать шаблон в `daily_task_templates.dart` (id, тема, текст, варианты, правильный ответ, объяснение, награда) и добавить id в список `allTemplateIds` — генератор подхватит его без изменения логики.

## 8. UX/UI и доступность

**Ключевые решения**
- Один главный экран: Рыжик, баланс, копилка, цель, показатели и задание дня видны сразу; всё остальное — в нижней навигации (Главная, Задания, Бюджет, Цели, Профиль).
- Короткие фразы, реплики Рыжика объясняют причину его состояния («Я проголодался: сытость 0. Покорми меня!»).
- Категории подписаны текстом и иконкой («Важное» / «Приятное»), а не только цветом.
- Нехватка монет никогда не приводит к тупику: показывается «не хватает N монет» и следующие шаги.
- Без запугивания и стыда: ошибка сопровождается спокойным объяснением и способом исправить.

**Доступность**
- Кнопки и карточки не меньше 48 × 48 dp.
- Основной текст — 16 sp и крупнее (шрифт Nunito); интерфейс адаптируется к системному увеличению шрифта (раскладка перестраивается при крупном тексте).
- Семантические подписи для экранного диктора у кнопок, карточек и выбора.
- Настройки: «Звук» и «Подсказки»; при системной настройке «Убрать анимации» Рыжик показывается статичным кадром.
- Портретная ориентация, ширина от 360 dp; проверено также на 412 dp.
- Действия, заметно меняющие прогресс (удаление профиля, сброс демо, снятие из копилки), требуют подтверждения.

## 9. Разрешения, данные и удаление профиля

**Разрешения Android**

| Разрешение | Зачем |
|---|---|
| `USE_BIOMETRIC`, `USE_FINGERPRINT` | Необязательный вход взрослого в родительский раздел по отпечатку/биометрии вместо PIN |
| `…DYNAMIC_RECEIVER_NOT_EXPORTED_PERMISSION` | Служебное разрешение AndroidX, пользователю не показывается |

Интернет, камера, микрофон, геолокация и контакты не запрашиваются. Приложение полностью работает офлайн.

**Собираемые данные** — только на устройстве, никуда не передаются:
- игровое имя ребёнка (можно вымышленное) и возраст для подбора сложности;
- PIN взрослого — в зашифрованном хранилище Android (Keystore);
- игровой прогресс: монеты, план, покупки, цели, состояние питомца, выполненные задания, журнал операций.

Аккаунтов, e-mail, телефонов, рекламы, аналитики и платёжных данных нет.

**Удаление:** Настройки → «Для родителей» → ввести PIN → «Удалить профиль и данные» → подтвердить. Удаляются профиль, прогресс, журнал операций и PIN; приложение возвращается к первичной настройке. Также можно удалить приложение или очистить его данные в настройках Android. Демо-профиль сбрасывается кнопкой «Начать демо заново».

## 11. Известные ограничения и план развития

**Ограничения**
- Размер APK ≈ 520 МБ: анимации Рыжика хранятся покадрово в 60 fps с высоким качеством. Установка и работа не страдают, но загрузка долгая.
- Только русский язык; интерфейс рассчитан на портретную ориентацию.
- Один детский профиль на устройство (плюс отдельный демо-профиль).
- Раздел для взрослого — на том же устройстве, без удалённого контроля (по ТЗ 2.7 не требуется).
- Звуковое сопровождение минимальное.
- Проверка на физическом устройстве — см. раздел 10.3.

**План развития**
1. Сжать анимации (WebP с потерями, меньше кадров для фоновых клипов) — цель < 150 МБ; разделить AAB по ABI.
2. Больше событий (скидка-ловушка, потеря кошелька, подарок от бабушки) и заданий по теме «платежи и карты».
3. Несколько детских профилей и настраиваемые родителем задания.
4. Озвучка реплик Рыжика для детей, которые только учатся читать.
5. Планшетная и альбомная раскладки.
6. Публикация в RuStore (карточка готова — `docs/rustore/`).
